# validation05 静态场景：方向段末端停滞的只读诊断

## 结论与范围

build10 的方向段 cursor 阻止了未完成上一方向段就跳到后续分支，但这一轮静态试验仍 timeout。机器人停在中间倒车段的换向点外约 7.6 mm，控制器持续主动选择零运动。不是感知不健康、重规划未交付、计算超时或碰撞安全检查禁止它运动。

这份文件仅分析已完整结束的 `static/v12_shared`，没有修改控制代码、构建、运行参数或旧对照记录；没有运行 ROS、shadow 控制、额外优化器或绘图。下述改进是未实现、未验证的后续方案，不构成 build10 已解决该问题的证据。

## 实际走的是哪个评分器

最后诊断的 `local_phase.strategy[0]=0`，没有动态障碍物。build10 的 `MPPI::plan()` 在这个分支交给 Legacy 控制器；最后决策来自 V7 `evaluate()`，不是 V12 `dynamicScore()` 的最终目标 endpoint 模式。

对应源码为 `builds/v12_shared_10/source/online_kernel.hpp:630` 起的 V7 `evaluate()`：

```text
过程：80 * nearest_curve_distance²
    + 0.6 * projected_tangent_yaw_error²
    + 1.5 * progress_deficit
终项：35 * nearest_curve_distance²
    + 0.5 * projected_tangent_yaw_error²
    - 12 * projected_arc_progress
另加：同一碰撞代价、控制变化代价。
```

`progress_deficit` 只有 `wanted_speed > 0.08 m/s` 时才启用。最终最近投影对应的 signed speed 是 `-0.066868319 m/s`，因此零速没有这一项的进度欠债。

最终最近曲线投影落在第 423 条边，边内比例约 0.796899；距离 `0.026038873 m`，插值后的投影 yaw `1.543480765 rad`，与实际 yaw 相差 `0.123649892 rad`。当前有向段尚余弧长约 `0.064773613 m`。

零运动的 3 s 评分可以仅从这些实测／参考量精确复算：

| 评分项 | 数值 |
| --- | ---: |
| 过程位置项 `3×80×distance²` | 0.162725493 |
| 过程 yaw 项 `3×0.6×yaw_error²` | 0.027520732 |
| 末端位置项 `35×distance²` | 0.023730801 |
| 末端 yaw 项 `0.5×yaw_error²` | 0.007644648 |
| 总和 | 0.221621674 |

这一总和与实际选中代价 `0.22162167394229584` 一致。零轨迹的弧长进度、控制变化与低速 deficit 均为零。

nominal 及非零候选可以在预测中进入 0.05 m 位置范围，但只能实际执行后由实测低速条件推进 cursor；预测不能直接切段。当前评分器却认为它们不如继续停在范围外。

这些候选最小 hard-margin gap 都约 0.2959 m，明显超过共同的 `comfort-hard_margin=0.02 m`，且没有动态目标，因此本次候选间代价差异不是碰撞代价导致的。未导出候选 yaw／逐项代价，不能把某个运动候选多出的全部代价定量归到某一项；源码和零轨迹精确复算支持“末端仍沿投影曲线／切线／弧长评分，没有显式 cusp 到达目标”的诊断。

## 为什么不是再调一个阈值就算修复

1. 加宽 cursor gate 会把这次停点标成到达，但它不能解释或消除“未到位停车最优”的评分结构；另一条曲线仍可能在新 gate 外停住。
2. 再降低碰撞权重无法解决这次问题，因为当前竞争候选的共同碰撞软代价没有激活。
3. build10 已提供能向 cusp 回接的 proposal，且搜索中确实存在这样的安全候选；只修 proposal、不改阶段末端评分语义，仍会被评分器拒绝。
4. 强制放行某个命令、预测提前推进 cursor 或取消最新执行／制动验证，都会混淆规划建议与执行授权，不是本任务允许的解决方式。

## 未验证的后续完整方案：实测驱动的 phase-end capture

保持整个原生束、真实最终末点、当前方向段关联、物理包络、margin、共同碰撞代价、CV 时域和最新执行／制动验证不变。只明确近中间方向段末端的任务语义。

### 1. 模式由本轮实际测量决定并冻结

对非最终方向段，在实际位置已接近 cusp、且当前有向段的实际有序剩余弧长也很小的时候，进入 `phase_end_capture`。不能仅凭直线距离判断，否则一条回环轨迹可能在开始时就离自身末点很近。

这个模式针对 `(reference_revision, phase_id)`：本轮所有预测候选使用同一个模式，预测接近／穿过阈值不改变模式、不推进 cursor。新参考／实际切段会重置模式；可设计成进入后锁定至实际切段，以避免边缘反复切换。具体进入范围与退出规则需要另行论证、测试，不能声称已经确定并验证。

### 2. proposal 指向可到达的 cusp 位置，而非尚无法满足的切线姿态

用差速模型生成旋转／接近／减速候选。接近方向应与当前有向段相容，并明确处理实际超越末点后的微小纠偏；参考关联不等于重新全面禁倒车。

到达位置之前，不强制追踪原曲线在 cusp 的瞬时切线 yaw。目标向量趋零时不能用 `atan2(0,0)` 制造转向；进入实际到达范围后提供制动／保持候选，不把中间 cusp 触发成整个任务的最终 yaw 对齐。

### 3. objective 同步使用 cusp 的欧式到达进度

在固定的 capture 模式内，将局部位置／末端位置误差解释为到 cusp 的距离，将 heading 误差解释为可实现接近方向的误差；进度使用：

```text
capture_progress = actual_initial_distance_to_cusp
                 - predicted_terminal_distance_to_cusp
```

不能继续把旧投影弧长增量当这一阶段唯一的进度；它可能要求小距离、高曲率末段上的暂时转向，而这又被切线跟踪项惩罚。近点时不要求任意固定 yaw，且所有候选沿同一固定模式评分。可以先复用已有位置／朝向／进度项系数来验证语义修复，不先通过反复调权重掩盖目标不一致。

该模式需要覆盖实际可能执行的 Legacy 静态评分／回接路径以及 V12 动态路径，不只是修改当前没有运行的 V12 `dynamicScore()`。

### 4. 真正切段仍由实际到达与低速决定

保留 `distance_to_cusp<=0.05 m && abs(measured_v)<=0.025 m/s` 的 cursor 条件。候选到达、预测停车或一条安全连接都不直接推进 phase。实际切段时再清除旧 warm／局部路线缓存，保留 actuator feedback，并让下一方向段承担它自己的有向跟踪或最终目标对齐。

### 5. 后续必须补的验证

- 在这份失败快照上检查非零可到达候选的 capture 评分是否优于范围外零停候选；同时确认仍通过原共同碰撞核与独立执行／制动检查。
- 验证曲线末端、横向偏离、微小超越、正反换向、回环附近和中间点 yaw 不一致。
- 验证候选不推进 cursor、新参考与实际切段正确清理模式；最终目标仍是完整束末点。
- 再做新的真实在线对照；保存所有成功／失败。离线评分通过不能代替闭环完成。

本轮没有实施这些改动。build10 这一静态失败须原样保留并作为未解决限制交付，不能用这份后续提案将它改记为成功。
