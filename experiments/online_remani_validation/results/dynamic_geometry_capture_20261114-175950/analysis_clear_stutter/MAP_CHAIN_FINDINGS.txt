There is no later merge magically turning a successfully computed sparse update into the global map.

3. Exact clock meanings and remaining waiting
h3 is md_.last_occ_update_time_, assigned ros::Time::now() after occupancy fusion completes (grid_map.cpp:2107). It is not the original LiDAR scan timestamp. True sensor-to-command latency also includes scan transport, pending-slot delay and occupancy work before h3.
h17 is exporter cache-refresh acquisition time immediately BEFORE cropped field copy (mppi_collision_export.hpp:214..222). It is set only when the field version or crop changes; repeated samples/delta messages retain previous h17. It must not be interpreted as every packet's publication time.
Across596 observed fields, h3→h17 median165.50 ms, p95289.30 ms, max344.64 ms. This includes worker work plus preparation, queueing, commit/read-snapshot copies and up to the exporter timer wait. No available trace separates all these subparts per job.
For186 observed full-field packet callbacks, h17→callback entry median13.38 ms, p9523.51 ms. This includes C++ field copy/body construction, output serialization, transport and scheduling; it is not pure communication delay. Python full decode median2.78 ms, delta decode median.312 ms. Callback adoption→checking median30.94 ms across the sampled statuses; the nominal MPPI loop runs at10Hz.
Observed distinct field-acquisition intervals median150.09 ms,p95299.98 ms,max549.99 ms; some fields can be missed by the10Hz status sampler. Pipeline commit throughput is the stronger rate estimate.
Source already drains completed work from the single map-writer loop within its nominal10ms wakeup (grid_map.cpp:251..264); it does not invariably wait a whole extra50ms ESDF timer. The exporter uses one independent20Hz sampleAndOutput timer (mppi_collision_export.hpp:327). Output frequency20Hz means repeated packets, not20 freshly computed ESDF generations/s.

4. Generation validity
GridMap::ReadScope(Complete) selects latest_complete_snapshot and requires occupancy_seq==esdf_seq (grid_map.cpp:98..111,177..187). During a newer occupancy update the previous complete map remains usable within its original TTL; there is no policy of invalidating every complete field merely because latest occupancy is ahead. Exporter's h4 additionally checks map readiness, fresh cached joints/odometry, finite geometry, ground/self-collision, dynamic layer validity and age. h30 accepted != h31 fused simply shows pending/coalesced LiDAR work; it is not itself a reason to invalidate the coherent selected generation.
Exporter max_age comes from dynamic_point_flow/max_age=.35 and is serialized in h15. Both map fusion age and enabled dynamic-observation age consume this value (active_arm_mppi.py:104..109). Consumer fresh state is recomputed at capture, after solve and before delivery. Refreshing h17 or wire sequence cannot renew h3.

5. Smallest justified next optimization work
Do not widen350ms or relabel old fields fresh. Preserve the completed-generation guarantee and actual delivery validation.
The data justify targeting the large EDT input domain / dense worker cost first. They do not justify randomly reducing the halo, changing the15% cut threshold, adding threads, or promising a gain from another timer tweak. Existing map-writer result-drain and independent exporter improvements are already present.
Before selecting a new spatial algorithm, use the existing worker on a bounded exact failing job: retain its occupancy bytes, changed coordinates, bounds and per-stage timings (already-supported MapTrace/LatencyTrace fields), then compare candidate partitioning with the current dense result at the actual capped-distance accuracy. A short bounded capture/replay is sufficient; no second mapping framework is needed. Full-window debug logs are absent here, and the available diagnostic crops cannot reconstruct out-of-crop dirty cells, so the current data cannot prove which partition rule should change.
In parallel, separately confirmed spurious geometry/occupancy must be corrected at its source; this can reduce both collision-triggered cancellations and needless map churn, but no specific compute-time saving should be claimed before measuring the changed-cell distribution again.
After that, validation must measure completed-generation cadence and capture/delivery age-margin distributions, not merely average EDT duration.
