# REMANI / V12 统一碰撞模型与参考回接

本版本只在隔离 ROS 数值闭环（SIL）中运行，固定机械臂，仍使用原生 REMANI 在线规划、重规划和实际发布的多项式轨迹。没有替换实车 launch、控制器或安装到 devel。它不是 Gazebo / 实车验收，也不是未经修改的上游 REMANI-Planner 的性能复现。

## 为什么不只增加“跟踪权重”

原 V12 的 MPPI 用二维三圆全身投影和自己的距离场、近障惩罚；原生 REMANI 用三维碰撞采样和 ESDF。原生判定可行的新参考，对 MPPI 可能仍处于碰撞余量或强排斥区。只提高跟踪权重既不能修复判定不一致，也可能让局部控制追逐不可执行的参考。

本版本先共享碰撞输入与几何，再调整新参考的接续逻辑。局部控制仍允许在真正有预测冲突时离开参考，不能强制贴轨穿过障碍物。

## 共用的几何、输入与空间代价

`shared_collision.hpp` 同时编译到隔离原生规划器与 MPPI 动态库。固定臂、底盘的完整二维投影由 `geometry.csv` 中三个圆的并集覆盖，不把机器人当作点，也没有缩小原先圆半径。真实臂自碰撞和地面约束保留；统一投影已经包含固定臂，避免再叠加另一份不一致的环境臂碰撞代价。

`shared_collision_node.py` 从实际检测器的分类点云和静态 PCD 构造一份原子快照：栅格距离场、目标外形/速度、固定臂全身投影、测量时间、健康状态和 sequence。两层接收同一发布源，不分别重新构造各自的地图。场景障碍真值只供传感器生成与独立评价，不进入控制器的目标估计或碰撞输入。

对第 i 个投影圆，静态表面距离为 `d_static_i = D(c_i) - r_i`；第 j 个目标的距离为 `d_dynamic_ij = ||c_i - o_j(t)|| - r_i - R_j`。`D` 是共用栅格的双线性插值，`r_i` 与 `R_j` 为物理覆盖半径。

共同硬约束是 `min(d_static_i, d_dynamic_ij) >= 0.10 m`。共同空间软代价为：

```text
J_collision = 50000 * sum_i [max(0, 0.12 - d_static_i)^3
                 + sum_j max(0, c_j - d_dynamic_ij)^3]
c_j = 0.12 + moving_j * min(0.12, 0.8 * ||observed_velocity_j||)
```

速度的单位是 m/s，0.8 的单位是秒。动态舒适区最大 0.24 m，静态舒适区为 0.12 m；它们都是软代价作用区，不扩大物理半径或硬安全余量，不恢复之前取消的 CV 不确定性半径。对地图与每个目标分别求和，避免“最近的静态物体”掩盖附近运动目标的软代价。

原生优化器的 xy/yaw 梯度与 MPPI 的候选代价来自同一实现。原生碰撞搜索、最终环境复核、最小距离与预测碰撞接口也接入该实现，不只是替换一个可视化图层或一个控制器权重。

## 新参考的接续

- 收到同目标新参考时清空旧 MPPI 暖启动、旧局部路径和已列出的动态侧向承诺，保留实际底盘速度反馈；build08 补清继承的静态绕行 `side`。这是具体状态的清理，不是整个控制器完全重置。
- 没有预测冲突的普通跟踪模式，横向误差权重由 5 调为 80、终端回接误差权重由 12 调为 35；有预测冲突时仍使用避让模式，不强制向障碍物中的参考回接。
- V12 专用终点捕获增加剩余路径弧长不超过 0.35 m 的条件；继承引导及仿真任务完成仍按最终姿态判断，此修改不是对所有多段路径按序执行的保证。
- 删除局部额外的静态宽区域终端排斥项，空间碰撞惩罚统一到上式；运动目标仍保留独立的闭合速度/终端时间风险项。

因此这是“共同空间模型 + 参考回接”的联合改进，不声称四组对照可以单独证明某一个权重或碰撞代价的因果贡献。

80/35 也不是所有分支强制追 REMANI：静态绕行模式可能对自己的局部连接路径评分；共同碰撞核不会取消必要的局部引导。静态回接门槛和分段投影关联仍要结合实际诊断分析，不能把所有剩余偏差都解释成碰撞代价。

build06 完整对照揭示了另外两处回接接口不一致，build08 做了针对性修正：

- 原静态显式回接要求 `gap>0.10`，相当于物理间距要大于 0.20 m，而共同模型的静态软代价在物理间距 0.12 m 外已经为零。实跑中新参考后的 227 个诊断周期 nominal 连接净距在 0.02–0.10 m，166 个周期仍留在局部绕行模式。现在仅对静态、共享模型，用 `comfort-margin=0.02 m` 累计回接清晰周期；仍要求整个 nominal 展开可行、连续 4 个周期，并保留发布时的实际控制与制动复核。动态门槛及非共享旧版本不改变。
- 局部连接路径原来总按新参考第一段的方向生成；当新参考先倒车再前进、车已进入后半段时，仍可能生成倒车连接。现在按当前空间投影所在参考段选择方向，不禁止倒车。重叠/自交的参考段仍需要进一步的时序关联，不能称为所有多段轨迹关联已经解决。

同时增加空暖启动反馈保护：新参考清空 `warm` 后，若当周期输入绑定失败、没有求解，反馈只更新实际执行速度，不访问 `warm[0]`。真实 C API 在开启 libstdc++ 边界断言的独立探针中验证了绑定失败、reset、正常反馈、旧 `side` 清除、倒车转前进连接、静态舒适区回接等分支。该探针没有 ROS 发布或控制实车。

## 仍然不相同的部分

原生搜索/优化冻结一次当前测量，MPPI 则用同一测量在候选的各个时刻做 CV 外推。两层的几何和空间代价已经统一，但优化时域、积分权重、控制目标和动态终端风险没有变成同一个算法。动态新参考仍可能暂时不可执行，MPPI 合理偏离不应被当作跟踪器故障。

原生求解完成时输入可能已经超过 0.35 s：它发布的是建议参考，不是执行放行。每次局部发布均重新绑定最新健康快照，复核实际选中控制展开和制动轨迹；保留 50 ms 求解截止时间、75 ms 控制租约和固定臂有效性检查。收到同目标新参考的瞬间，正在求解的旧参考候选最多可以在最新碰撞验证通过后执行一个控制周期，下一周期清暖启动；不为了参考版本切换人为插入停车。

共用快照由专用 CallbackQueue / 单线程 AsyncSpinner 接收，只做校验与原子指针替换；原生地图和规划状态不跨线程修改。优化仍固定一帧，而原生当前安全检查可读取求解期间收到的新帧。构建06还固定静态存储与接收线程的构造顺序，退出时先停止/等待接收线程，再释放其回调队列和共享存储。

继承的 MPPI 静态安全余量恢复策略仍允许“初态已侵入 0.10 m 余量但没有物理碰撞”的状态逐步恢复余量；原生硬检查没有该例外。不能宣称两层在这种初态下硬约束处理完全一致。

## 为什么保留动态软运动余量

仅采用静态 0.12 m 舒适区的开发构建，动态贴边候选在物理距离大于 0.12 m 时没有空间软惩罚，进度收益鼓励侧移不足；之后首指令的制动复核拒绝了全部备选，停止的机器人被继续靠近的迎面目标撞入投影。

这些失败完整保留在 `results/shared_collision/development_03_head_on`（build02）和 `development_04_head_on`（build03）。并不是感知晚或收到新参考才停。build04 将速度相关软作用区加入两层同一个代价核，硬外形和 0.10 m 余量不变。

开发记录 `development_05_head_on`（build04）到达目标、最小实际物理间距 0.243 m。运动后约 7.5–10.8 s 的选中候选安全净距维持约 0.12–0.13 m（已扣硬余量），此前失败候选则从约 0.09 m 衰减到 0.007 m；新记录没有候选被制动检查以 code5 拒绝。不过它发布 10 个参考 bundle、全程约 40.95 s，旧 V12 该场景记录为 2 个、约 33.82 s。安全恢复不能等同整体效率已优于旧版，更不能把单次开发试验视为统计结论。

第一批 build04 四组对照 `validation_01` 另外暴露了输入接收接口缺陷：native-only 组同步求解阻塞共享输入回调，发布后立即把旧输入当成安全不可执行而急停，空旷机器人也不动。这一批已中止并保留 `suite_interruption.json` 和已完成记录，不能拿它作最终性能对照。build05 是线程解耦中间构建，未用于正式试验；build06 是补齐退出资源顺序后的候选，正式重新使用独立 `validation_02`。

`validation_02` 已完成全部 24 轮并保留完整结果，35 个 GIF 的 4757 帧全部解码通过。静态新参考后误差 P95 两次分别为原 V12 0.224/0.217 m、统一模型 V12 0.099/0.093 m，但统一版用时更长，不能只报告误差优势。新参考本身引入更长的正反向路线，也是用时差异的一部分。

build07 是局部安全补丁的失败编译记录（基类错误调用派生类弧长函数），没有被运行或发布为完成构建。build08 使用局部累积弧长修正该实现，原生三个二进制与 build06 逐个 SHA 完全相同，只重编译局部 MPPI 库；全部数学测试及边界断言探针通过。没有覆盖旧构建。

## 回接与恢复争抢的确证

build08 的 `validation_03` 六轮补充试验有五轮到达、一轮静态重复超时，没有投影碰撞。该失败必须保留，不能因为单位测试通过就认定整体回接已解决。

失败的第二参考在 16.500 s 交付，先倒车后前进；中途换向后的正向段还有 1.167 m。最后 20 s 的 400 个诊断周期全部执行验证成功，没有 deadline、制动拒绝或无解。回接与继承恢复却选出相反第一拍：

| 时间/s | nominal gap/m | 控制策略 | 实际指令(v,w) |
| --- | ---: | --- | --- |
| 45.103 | 0.03865 | 已复核原生回接 | (0, +0.8) |
| 45.204 | 0.03872 | 旧恢复覆盖（回接仍可行） | (-0.08, -0.8) |
| 45.395 | 0.04277 | 已复核原生回接 | (0, +0.8) |
| 45.500 | 0.03911 | 旧恢复覆盖（回接仍可行） | (-0.08, -0.8) |

最后 clear_count 已到 347，不是共同 0.02 m 回接门槛挡住了路线。V7 已选出同一原生参考下的可行回接，外层 Legacy 仍依据旧 0.04/0.10 门槛、缓存局部路线和必须有平移进展的恢复准则，反复把回接重写。预测中能转完并前进，但实际每周期只执行互相抵消的第一拍。

build09 统一这一个策略所有权：仅健康共享输入、静态、V7明确 checked native REJOIN、无干预标志且有完整控制展开时，再针对原生参考复核整个展开；可行且在共同舒适区外，就关闭旧恢复、执行该回接，不允许另一份局部引导启发式再次覆盖它。普通候选无此捷径，动态策略和旧恢复阈值不改，最终最新帧实际控制/制动校验仍是执行放行条件。旋转暂时没有平移进展不是需要换另一方向的理由。

新增边界断言探针可在 build08 稳定复现这个冲突（返回码15），不是只凭 GIF 猜测。该失败也保存在 `unit_state_conflict_08`，后续候选必须通过同一个探针及在线复测。

## 换向点的参考关联失败（build09）

build09 通过了上述争抢回归，但 `validation_04` 六轮在线补测仍有两轮静态超时；空旷、单横穿、迎面和四目标到达。不能把局部单位测试通过写成回接问题已全部解决。

静态主试验的新参考第 299/300 点同为 `(2.02474, -1.05226)`，朝向也相同，但速度分别为 `-0.05/+0.05 m/s`，是先倒车再前进的换向点。数值底盘状态到达附近 `(2.03387, -1.05755)` 后，与两段的最近距离完全相同，约 0.01055 m。旧投影循环只在距离严格更小时替换结果，因此总认成前一个倒车段；引导目标已在车后，停车候选的代价反而最低。

该记录最后 20 s 的 400 个诊断周期全部计算成功、执行验证通过，模式是普通跟随而不是恢复或无解，实际指令为零，计算约 1.4 ms。所以这个失败不是碰撞代价过大、制动检查拒绝、感知迟或算不出来，而是同一位置的前后运动阶段缺少明确关联。另一轮静态超时还有恢复和偶发执行拒绝，需要单独保留，不能仅凭这个案例就认为全部静态失败同因。

下一候选只在隔离局部库引入测量态的有向参考阶段：保留完整未来轨迹与真正任务终点，限制当周期投影/连接/引导属于当前运动方向段；接近当前换向点并减速后才进入下一段。候选展开不能自行推进这个阶段。它不改变共同碰撞模型、硬余量、底盘限速、最终最新帧执行/制动检查；新增模式必须经过回归，不直接放行到实车。

## 有向参考阶段实现（build10）

`directed_reference.hpp` 是独立的纯 C++ 阶段游标，由完整采样参考的有符号速度划分连续前进/倒车阶段；相同方向的多个多项式片段不会人为产生换向。实际 C API 入口每周期只更新一次游标，所有候选只读取相同的阶段快照。新参考先绑定第 0 段，随后实测距当前换向点不超过 0.05 m、线速度绝对值不超过 0.025 m/s 才单步切换，不要求角速度归零。前/后退避障控制本身不被硬禁止。

原生参考完整保留，不使用 Python 切片或把换向点冒充导航目标。原生投影、连接点和前视引导限定在当前有向阶段；局部连接路径另行映射自己的 `local_end/local_gear`，不得继承原生点号。只有最终阶段启用原完整束末点的 goalCapture；这改变了终点模式的启用资格，不能声称所有终点策略字节不变。

预测进入换向捕获区时刹车/保持，但预测不能切换游标；下一实测低速周期才切换。初始阶段末速度为非零也会减速；若只是投影被夹到段尾、车身横向仍偏离换向点，则仍给出可达回接，不因弧长为零永久停车。切段清除暖启动、旧路线、绕行侧和恢复缓存，但保留实际执行反馈。

build10 从不可变 build09 只重编局部库，三个原生二进制和共用碰撞头的 SHA 均不变。数学 120 姿态、原控制状态 8 项、游标 18 项和实际控制器 26 项边界断言检查通过；保存的 build09 静态混合方向参考几何也通过阶段检查。该几何回归使用合成边界测量，不是重放成功、物理安全或实车验证。正式在线结果另见对应批次，不能以这些检查替代在线回归。

阶段变化保存在 `roslogs/*/base_mppi-*-stdout.log`，包含参考身份、阶段、方向、范围、实测状态和切换时检查的换向距离。`audit_directed_reference.py` 可与完整 consumed reference 对照检查阶段顺序、范围和实测切换门槛；FNV 仅是遥测身份，原参考 SHA256 另行保留。该审计不是碰撞安全证书。

build10 的 `validation_05` 六轮新在线结果为五轮到达、一轮静态主试验超时，全部没有保守投影碰撞；不能据此宣称全部场景安全或静态回接已经修好。静态重复试验在 36.804 s 完成一次合法切段（距换向点 0.04392 m、实测 v=-0.02312 m/s），43.994 s 到达；静态主试验却停在距换向点 0.05760 m 处，超出 0.05 m 门槛，没有切段。原生随机搜索未配对，两条新参考不同，不能拿重复成功掩盖主试验失败。

主试验末段走的是 Legacy/V7 的静态评分：仍以最近曲线距离、原生切线朝向和弧长进展计分，没有同步给当前阶段末点的欧式到达目标。附近参考速度约 0.05 m/s，又低于进度欠债项的 0.08 m/s 启用阈值，所以停车不承担该项欠债。主试验末尾停车期间求解、最新帧执行验证均通过，无动态目标；这是近换向点“引导目标与评分目标语义未完全同步”的失败，不能靠扩大切换门槛或再改碰撞半径解释。

下一研究步骤是把**实际测量选择的阶段末端捕获模式**同时接入引导和评分：捕获当前阶段末点时，以可达接近朝向和欧式距离减少量衡量推进，直至实测满足切段门槛；所有当期预测共享固定模式，不能预测切段或把阶段末点当任务终点。完整原生目标和硬执行验证保留，真实动态冲突仍可优先避障。这个方案尚未实现和验证；本轮没有继续叠加未经复测的 build11，也没有放行 build10 到实车。

## 对照与验证

预先定义四组：当前工程 REMANI（关闭 MPPI）、原 V12、统一模型 REMANI、统一模型 V12；五个场景：空旷、新静态障碍、单个横穿、正迎面、四个运动目标。额外把四组静态场景各重复一次，共 24 轮。原生随机搜索未做配对种子，不宣称统计成功率。旧控制器与局部执行器租约不同，原生几何的改变也在四组中独立保留。

数学验证：120 个姿态与独立 Python 代价、有限差分梯度及单独编译的原生共用核一致；build04 最大代价误差约 3.64e-12、最大梯度误差约 1.24e-5。还验证新参考清暖启动、最新障碍帧否决旧控制、预测时域越界拒绝与 5 s 空旷跟踪。它们验证共同核与 C ABI，不代替原生 hooks 的在线集成试验。

比较统计使用实际状态而非控制器宣称的状态。停车同时要求线速度与角速度低，并剔除启动等待和近终点；新参考后误差剔除最初 0.5 s，另外统计无预测冲突时的误差。最近路径距离、连续分支距离、参考物理净距均保存。原生-only 的参考图标注为发布回放，不冒充控制器接收确认。

[24 轮初始完整对照](results/shared_collision/validation_02/README.md)；[build08 补充验证（含超时）](results/shared_collision/validation_03/README.md)；[build09 回接策略所有权验证](results/shared_collision/validation_04/README.md)；[build10 有向阶段回归（仍有静态超时）](results/shared_collision/validation_05/README.md)。各补充批次仅 6 轮统一模型 V12 是新在线试验，18 项未改变的本批控制记录经源/参数/二进制哈希核验后只读复用，逐项记录真实来源；不是 24 轮新的配对试验。原始失败与开发记录不删除，搜索图来自实际候选记录，不重跑控制器补画不存在的搜索。

净距与碰撞评价使用保守二维全身投影，而非 Gazebo 三维物理接触。原生-only 组的失败不表示未经修改上游论文算法的能力，也不能把投影包络相交直接称为实车金属外形已接触。

## 复现与回退

输出目录必须尚不存在。在线对照入口要求显式指定 `--shared-build`，不会把一个有失败记录的候选默认为获准版本。ROS 图强制使用 localhost:11441，只有 `/sim/` 底盘命令，不加载底盘/CAN/机械臂驱动。

```bash
cd /home/l/remani_ws
source /opt/ros/noetic/setup.bash
source devel/setup.bash
python3 experiments/online_remani_validation/compare_shared_collision.py \
  --shared-build experiments/online_remani_validation/builds/v12_shared_10 \
  --out experiments/online_remani_validation/results/shared_collision/my_comparison
```

只重绘已有记录：`python3 experiments/online_remani_validation/compare_shared_collision.py --out <已有结果目录> --render-only`。失败的旧派生图片不被静默覆盖。

在已完成的 build06 四组控制记录上补充测试有向阶段候选（仍有静态失败，并非实车放行版本；输出目录必须不存在）：

```bash
python3 experiments/online_remani_validation/compare_shared_followup.py \
  --controls experiments/online_remani_validation/results/shared_collision/validation_02 \
  --shared-build experiments/online_remani_validation/builds/v12_shared_10 \
  --out experiments/online_remani_validation/results/shared_collision/my_followup
```

该入口核验 24 项原始记录完整、在线 Python 未改、所复用原生二进制和共同碰撞核与新构建相同；原 V12 的库也必须相同。新报告不会穿过符号链接改写旧控制记录，新的派生统计写入 `reused_analysis`。

原 V12 入口 `run_native_v12.py` 的默认构建仍是 `native_v12_07`。新构建使用独立 archive / binary，不运行 catkin install、不覆盖生产源码或 devel 输出；停止隔离实验即回到原流程。这次实验的新代码与数据没有自动推送 GitHub，也没有实车放行。
