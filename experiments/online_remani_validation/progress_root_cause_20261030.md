# 后端轨迹联合可行性根因排查

用户任务：全面追查轨迹交付失败，找到能够复现、验证的原因。

起点证据：endpoint_time_20261030_01 中，首尾片加时组初始轮加速度合格，最终轮速合格但左轮加速度超过原生验收线 5.59%；两组均未交付。旧输入的全片加时成功不能代替当前输入。

本轮工作：

- 核对最新源码、原始候选、历史梯度和采样检查范围。
- 独立分析速度/加速度/jerk 与轮约束峰值的变化。
- 追踪实际接受迭代、分项代价与联合可行性；同输入小规模干预验证机制。
- 依据发现继续排查，记录失败和解释范围。

实验在隔离文件中进行，不覆盖生产或冻结历史。磁盘起始可用约 203 MiB，优先复用编译产物与压缩诊断输出，不删除历史数据。

已完成的自适应排查：

1. 分解当前四条候选的原生平滑、轮约束、低速、时间及固定臂自碰软项；用细步差分验证敏感坐标，粗步差分的百分比误差没有被误报为梯度实现错误。
2. 从历史ESDF/overlay gzip恢复完整原生查询状态，直接链接原隔离优化器库。四个检查点成本一致，两个初始梯度哈希与历史逐位一致。
3. native_run_01：首尾加时相同输入，0.6秒仍失败；1.2秒预算下0.709319秒首次原生通过，0.886065秒正常结束。旧末候选沿小下降步也完整通过3D和轮检查。
4. native_run_02：当前工程原始初始化（不是原版项目默认约束）0.6/1.2/3秒均没有通过。3秒组2.759秒正常停止，但留下碰撞。
5. native_run_03：原碰撞点重启、单独收紧delta，均未消除该碰撞。K16实际成本节点包含15个硬碰撞点；障碍积分独立复算一致，地图梯度有效。
6. 分项完整梯度显示：该停点首段内点xy占总梯度平方范数99.664%，碰撞梯度主要在后续段；沿碰撞下降方向可同时降低总目标及轮成本，故不是物理约束必然冲突。
7. native_run_04：同一停点同预算0.6秒、同delta/目标/硬门，只变固定对角尺度；原坐标失败，缩放组0.187555秒首次通过且最终通过。计算尺度另用1.076469秒，必须计入实际开销。
8. native_run_05：从未经加时的原始初值开始，固定尺度组0.332840秒首次通过，1.2秒截止时最后accepted仍通过。尺度预处理1.074304秒，首次通过合计1.407144秒。不是0.333秒完整请求交付，更不是在线实车验证。

当前已用干预验证的机制：局部变量数值尺度悬殊使原坐标优化微步停滞；较短预算截断仍可修复的候选；总成本相对变化停止条件可在碰撞仍存在时结束。物理轮限、外形、安全验收均未放宽。严格轮限和短段初始化是触发困难的条件，不能再把原因单独归结为轮限太紧。
