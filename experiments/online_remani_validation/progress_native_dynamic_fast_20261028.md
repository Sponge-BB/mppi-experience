# 2026-10-28：动态分支去重与重新闭环验证

## 要回答的问题

保留现有碰撞模型、搜索路线和执行规则，只省掉无用计算，能否让动态避障更及时？
不是通过少检查机器人外形、缩短预测时间或放宽超时门槛来让结果好看。

## 本轮修改范围

- 父版本：`builds/native_realtime_20261027_01`，保持不变，可直接回退。
- 新隔离版本：`builds/native_dynamic_fast_20261028_01`。
- 仅重编MPPI；REMANI、地图、跟踪和机械臂模型二进制字节复用。
- 动态候选已确定碰撞时，提前结束无用代价计算。
- 同一轮中的nominal路线复用碰撞查询；保留早退间距与完整代价的区别。
- 160个球、预测时域、采样数量/次序、随机数、50ms门槛、75ms指令有效期均不变。
- 生产`src/devel`和实车入口不改。仅localhost隔离ROS和`/sim/*`执行。

## 预先约定的验证

1. 单元测试、父版本哈希核验、关闭开关精确回退。
2. 固定输入回放：覆盖空旷、动态出现、干预、连续超期和无可行候选，不只挑最快的输入。
   每策略重置控制器/RNG，输入身份一致；这不等于恢复历史完整内部状态。
   非profile计时交错重复；profile另外运行，只解释工作量。
   对比可行分类、选中动作/控制序列和审核结果；拒绝候选的无用代价允许改变。
3. 新开关OFF/ON都设置`NATIVE_REALTIME_DEMAND=1`，重新运行static、crossing、head_on三个场景。
   同seed11、同障碍规则；次序交错，全部失败保留。每轮55秒，不因结果不好换种子。
4. 计时实验结束再生成图片/GIF；总结用直白的话叙述，不把回放提速当避障成功。

## 结论边界

这是固定机械臂、差速底盘的ROS数值闭环，不是Gazebo或实车验收。
单种子配对用于检查具体故障，不报告总体成功率。
若仍超时或碰撞，如实保留，不能声称动态避障已经解决。
